## Why

`index.md` is generated by `scripts/wiki.py compile` and is also published as the VitePress
site homepage (it is not in `srcExclude`). Its template still carries content written for the
**maintainer LLM working inside the repo**: a "Quick greps" block of `grep … wiki/` shell
commands and a preamble instructing "an LLM answering any question… should read this page
first, then narrow with `grep`." But the website's two real audiences — human visitors and
fetch-LLMs ingesting pages over HTTP — have **no shell and no `wiki/` directory**. The grep
block is useless to humans and actively misleads a fetch-LLM into trying to access a
filesystem it does not have. The canonical grep cookbook already lives in CLAUDE.md §11
(which is correctly excluded from the site), so the homepage copy is redundant at best and a
hallucination trap at worst.

## What Changes

- Remove the `## Quick greps` shell block from the generated `index.md` template in
  `scripts/wiki.py`.
- Remove the LLM-maintainer-oriented preamble ("An LLM answering any question… narrow with
  `grep`…") from the template.
- Replace that space with **web-native wayfinding** aimed at the two web audiences:
  - For humans: pointers to the client-side search, the [Tags](./tags) browse page, and the
    existing first-layer reference table.
  - For fetch-LLMs: a pointer to `/llms-full.txt` as the single-fetch machine-readable dump,
    and retention/light-strengthening of the first-layer table as structured data.
- Keep CLAUDE.md §11 as the **sole canonical home** for the `grep wiki/` cookbook (no
  duplication on the site).
- Recompile (`python scripts/wiki.py compile`) so the committed `index.md` reflects the new
  template, and verify the built site.

## Non-goals

- No change to `llms.txt` / `llms-full.txt` generation — they already exist
  (`llms-txt-export`); this change only *points to* `/llms-full.txt`.
- No split into separate "maintainer" vs "published" index outputs (a single template stays;
  option 2 from exploration is deferred — YAGNI).
- No change to the cocktail card schema, the tag vocabulary, or the first-layer table's
  columns/data.
- No removal of the grep cookbook from CLAUDE.md §11 — it remains the canonical home.
- No change to VitePress config, search provider, or the Tags page itself.

## Impact

- `scripts/wiki.py`: the `INDEX_TEMPLATE` string (the preamble line(s) and the `## Quick
  greps` fenced block; the "Browse by" section may be folded into the new wayfinding).
- `index.md`: regenerated output (committed artifact) changes — never hand-edited.
- Published site homepage at `https://c892836a.github.io/CocktailDex/` changes its intro copy.
- No code consumers, APIs, or dependencies affected; CI stays Node-only.
